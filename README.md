# 猫娘工具箱

一个小工具箱，左侧切换工具，右侧是该工具自己的标签页。目前有：

- **文件夹恢复** —— 记录当前打开的所有资源管理器窗口与标签页，之后一键原样恢复；
- **字数统计** —— 粘贴文字实时统计字数、字符数、行数、段落数、中英文细分；
- **JSON转MD** —— 粘贴 JSON 直接看 Markdown 排版效果，可开独立大窗口缩放查看，
  一键把正文送去「字数统计」或「翻译」；
- **MD浏览器** —— 把 Markdown 文本直接贴进来就排版预览，可开大窗口、可搜索；
- **翻译** —— 左右对照的中英（及 30+ 语种）翻译，可选风格、领域、术语，三档模型。

这些工具只是我个人工作中常用的辅助小工具，仅调优到适配我个人的工作。其他使用者可以根据自己的情况让AI帮你调试甚至添加自己需要的小工具。

## 本仓库是什么

这里放**源码**，能在 Windows 10 / 11（64 位）+ Python 3.9+ 上跑起来。
仓库里只有代码：编译好的单文件 exe 走 **Releases**，本地的 `data/`（里面有 API Key、文件夹记录与预设）**不进 Git**。

## Windows 拦截 / 报毒怎么办

**下载后很可能被拦一次，这是打包方式导致的误报，不是文件真有问题。**原因有两条，叠在一起就很容易触发启发式判定：

- exe 是 **PyInstaller 单文件**，启动时要把自己解压到临时目录再运行，行为和「释放器」类恶意软件的特征重合；
- **没有代码签名证书**（个人项目，证书要年费）。

> 版本信息资源这一条**已经补上了**：右键 exe → 属性 → 详细信息，能看到版本 `1.0.0`、公司 `Charming` 与产品说明。这能降低一点触发率，但不足以解决问题（前两条才是主因）。

### 三种拦截形式，对应三种处理

| 拦截形式 | 处理办法 |
|---|---|
| SmartScreen 蓝屏「Windows 已保护你的电脑」 | 点「更多信息」→「仍要运行」 |
| Defender 直接隔离或删除 | Windows 安全中心 → 病毒和威胁防护 → 保护历史记录 → 找到这条 → 「操作」→「允许在设备上」；再把解压目录加进「排除项」 |
| 浏览器提示「通常不会下载此文件」 | 保留 → 「仍然保留」 |

更省事的一招：**先解压，右键 exe → 属性 → 勾选「解除锁定」→ 确定**，再双击运行。

### 为什么可以放心（你可以自己核对）

- **联网只有一处**：「翻译」会请求 `https://dashscope.aliyuncs.com`（阿里云百炼，用你自己填的 Key）。另外四个工具全程纯本地，不联网、不上传任何文件。

## 使用

双击 `猫娘工具箱.exe` 即可，无需安装（exe 从 [Releases](https://github.com/charming386/Neko-Toolbox/releases/latest) 下载，或按文末自己打包）。

**界面结构**：左侧竖栏是**工具**（文件夹恢复 / 字数统计 / JSON转MD / MD浏览器 / 翻译）；右上角是该工具的**标签页**
（文件夹恢复里是「文件夹恢复」「预设」两页）。标题栏右侧的齿轮按钮打开**设置**窗口。

**单实例**：程序已经在跑的时候再双击，不会开第二份，而是把原来那个窗口（即使是最小化的）还原到前台。
所以任务栏和后台永远只有一份。想特意同时开多份（调试用）可以设环境变量 `FR_ALLOW_MULTI=1`。

## 工具一：文件夹恢复

- **记录当前打开的文件夹** —— 抓取当前所有资源管理器窗口，以及每个窗口里的标签页（顺序、当前显示哪一个都会记下）。每次记录会**覆盖**上一次的记录。
- **恢复已记录的文件夹** —— 按记录重建窗口和标签页。

> 记录时如果遇到系统读不到的窗口（后面那条会解释），程序会自动去读它们的标签 —— 这属于自动化窗口操作，
> 屏幕右下角会弹出提示条「正在读取文件夹 / 请勿移动鼠标，也不要进行其他操作」，读完自动收起。

> 关于「刚打开的窗口」：Windows 把新窗口登记进 Shell 需要约 1~2 秒，所以记录前会自动等一下，
> 确认桌面上的窗口都读到了再保存（都读到就立刻返回，不拖时间）。
> 如果还有窗口读不到（Win11 偶尔会把窗口放进独立的 explorer 进程里，这种窗口系统不给枚举），
> 记录完会在下方状态栏里写明「没读到：xxx」，不会悄悄少记。

### 标签页：预设

- **把当前窗口存为预设** —— 给当前这组窗口起个名字存下来，可以有任意多个。
- **手动添加预设** —— 直接输入文件夹路径（可粘贴、可浏览选择），拼一组预设。
- 左侧点任意预设，右侧就能看到它包含哪些窗口、哪些标签页。
- 支持重命名、用当前窗口覆盖、删除。
- **编辑文件夹**：预设详情里点「编辑文件夹」，可以手动**增删里面的文件夹**。
  列表按窗口分组（「窗口 1 · N 个标签」），选中某个文件夹点「移除选中」即可删掉；
  添加时默认放进最后选中的那个窗口，想单独开一个窗口就点「新建窗口」。
  某个窗口里的文件夹被删光，保存时这个窗口就不再保留；名称也能在这里改。

**替换模式（每个预设单独一个开关）**

预设详情底部有个「替换：先关闭现有文件夹」的开关，开启后这个预设的恢复流程是：

1. 先把当前**所有资源管理器窗口关掉**（一个窗口里多个标签页会整体关掉，不会挨个弹确认框）；
2. 再按预设打开对应的窗口和标签页。

关掉开关就是原来的行为：直接在现有窗口旁边把预设里的文件夹打开。开关状态跟着预设一起存在
`data/presets.json` 的 `replace` 字段里，换台电脑拷 `data/` 就还在。

## 工具二：字数统计

上方一个大输入框（纯文本、不带格式），下方是统计卡片：

| 统计项 | 口径 |
|---|---|
| 字数 | 中文汉字数 + 英文单词数（中文写作常用口径，**必选**） |
| 字符数 | 全部字符数，含空格与换行 |
| 行数 | 按换行切分的行数 |
| 段落数 | 默认按回车分段（空行不额外算，等于非空行数）；可在设置里改成按空行分段 |
| 中文字数 | 汉字个数 |
| 中文字符数 | 汉字 + 中文标点 |
| 英文词数 | 英文单词个数 |
| 英文字符数 | 英文字母个数（不含空格） |

- **实时统计**：输入停止 120ms 后自动计算，不用点按钮；右下角会显示这次统计的耗时。
  实测 5 千字约 1ms、5 万字约 8ms、20 万字约 37ms，所以长文本也不会卡（超过 5 万字/20 万字
  会把节流间隔自动放宽到 300/600ms）。
- **清空**：输入框**右上角**那个小按钮，一点就清空全文、统计立刻归零。
  框里没内容时它是灰的（点了也没意义），所以不会误触。
- **省电**：切到别的工具或标签页时不做任何计算，只记一个「待更新」标记，切回来再算一次。
- 显示哪些统计项在**设置**里勾选；「字数」是必选项、不可取消。
- **段落数口径**也能在设置里切换：「按回车分段」（一行一段，空行不算）/「按空行分段」（连续空行才另起一段）。

## 工具三：JSON转MD

把 JSON 粘到左边，右边立刻显示 Markdown 排版效果。

### 它是怎么挑正文的

**不是写死只读 `markdown`**，而是按一个**候选键列表**顺序找，取第一个「有内容的字符串」：

```
markdown → md → content → body → article → text
```

- 命中哪个，右上角状态栏就写「取自 xxx」（比如 `取自 markdown · 12,365 字符`）；
- 所以 JSON 里同时有 `markdown` 和 `summary` 时，**只会用 `markdown`**，`summary` 一个字都不会混进正文
  （想反过来用 `summary`，去设置里改，见下）；
- 列表里一个都没有时，才退回「通用 JSON 转换」（对象→小标题+键值、对象数组→表格、数组→列表，`title` 当 H1）。

**容器层级**：`ai_content` / `article` / `data` / `result` / `post` 包一层都认；
整段被包成字符串（`"markdown": "{...}"`）或者 JSON 里又套一层 JSON 字符串，也会自动拆开。

### 标题写法会被统一规范

`#` 和文字之间有没有空格，决定这个标题**能不能被识别**，不同解析器还不一样：

| 写法 | Python-Markdown | CommonMark（公众号 / Typora / GitHub） |
|---|---|---|
| `# 标题` | ✅ | ✅ |
| `#标题` | ✅ | ❌ 当普通段落 |
| `#　标题`（全角空格） | ❌ | ❌ |

所以转出来的时候**统一补成「`#` + 一个半角空格 + 文字」**，三种写法都能正常显示成标题，
复制出去粘到别处也不会掉成普通段落。

两处**故意不动**：

- **围栏代码块**（``` / ~~~）里的内容 —— 那是代码，改了会坏；
- `#include` / `#define` / `#hashtag` 这类以 ASCII 字母开头的 —— 可能是指令或话题标签，
  不是标题。只有紧跟中文/日文/韩文、全角字符或 emoji 才判定为「挤在一起的标题」。

> **历史上的一个坑**：以前加过一条「H1 跟 `title` 字段重复就去重」的逻辑，想避免预览里
> 出现两个标题。但 `title` 字段**在预览里根本不渲染**，所以这条逻辑的唯一效果就是
> **把正文的 H1 删掉** —— 而且那条正则只在「`#` 后有空格」时匹配，于是 `# 标题` 被吞、
> `#标题` 反而留着，看起来就像「有时候标题莫名其妙没了，全看有没有空格」。
> 现在去重已删除，`clean_markdown()` 一行标题都不删，只做规范化。

### 正文键可以改（设置 → JSON转MD）

- 6 个内置候选键各一个复选框，勾上的才参与、顺序就是列表顺序；
- **另外要提取**：填候选列表里没有的键（逗号分隔），例如 `summary, body_html`；
- **不要提取**：黑名单，**优先于勾选**（勾了 `text` 但写进「不要提取」就等于不用）；
- 面板底部会实时显示「当前顺序：markdown → md → …」，勾完立刻按新规则重转一遍，不用重开。

### 其它

- **预览里搜索**：<kbd>Ctrl</kbd>+<kbd>F</kbd> 或点标题栏右边的**放大镜按钮**打开搜索框，
  输入即高亮全部命中并显示「3/12」；<kbd>Enter</kbd> 下一个、<kbd>Shift</kbd>+<kbd>Enter</kbd> 上一个、
  <kbd>Esc</kbd> 关闭。大窗口预览里同样可用（快捷键在哪个窗口按就搜哪个）。
  搜索框是**内联在标题栏那一行**的，弹出时不会把正文往下挤；
  主界面这一行空间有限，搜索期间会把「复制 Markdown / 大窗口预览」临时收起，关掉即恢复。
- **更新预览**：不等防抖、立刻重转（<kbd>Ctrl</kbd>+<kbd>Enter</kbd> 同效）。
- **统计字数**：预览下方那个按钮，会把转出来的 Markdown 直接塞进「字数统计」并跳过去
  （它统计的是 Markdown 原文，`##`、表格竖线这些都算字符）。
- **没有 markdown 字段的普通 JSON**：自动转成 Markdown —— 对象变「小标题 + 键值」、
  对象数组变表格、数组变列表，`title` 会当成 H1。
- **预览**：Markdown → HTML 后显示，支持标题 / 表格 / 列表 / 引用 / 代码块 / 脚注 / 链接。
  **改完 0.15 秒自动重绘**，不用点按钮；想立刻看就点底部「更新预览」或按 <kbd>Ctrl</kbd>+<kbd>Enter</kbd>。
  预览下方会显示「更新于 hh:mm:ss」，一眼能确认刚才那次改动生效了没有。
  重绘会保留原来的滚动位置，改中间某一句不会跳回顶部。
- **大窗口预览**：点右上角「大窗口预览」开一个独立窗口，可拉伸、可缩放
  （`-` / `+` / `重置` 按钮，或 <kbd>Ctrl</kbd> + 滚轮，范围 60%~240%）。
- **另外两个按钮**：「复制 Markdown」把清洗后的正文复制走；「打开 JSON 文件」直接读文件。
- **底部三个去向按钮**（都在预览下方）：
  - **更新预览** —— 不等防抖，立刻重转（<kbd>Ctrl</kbd>+<kbd>Enter</kbd> 同效）；
  - **统计字数** —— 把 Markdown 原文塞进「字数统计」并跳过去；
  - **送去翻译** —— 把正文**放进翻译的输入框**并跳过去。**不会自动翻译**，
    语种确认好之后仍然要自己点「翻译」按钮 —— 翻译按字符计费，发不发该由你决定。
    跳过去时顶部会提示「已放进翻译输入框，确认语种后点『翻译』」。
    超过 12000 单位会被截断并提示（见「输入上限」那节；中文一字算 2 单位）。
- **封面**只显示一行提示（`封面：<url>`），不下载、不插进正文 —— 和投稿排版器的口径一致。

限制（都是有意为之）：

1. 预览用的是 `QTextBrowser`，支持 HTML4 + 常用 CSS，**不保证和 Word / 浏览器像素级一致**；
2. **网络图片不加载**，本地图片会按 JSON 文件所在目录找（所以从「打开 JSON 文件」进来时图能显示）；
3. 不做代码高亮（要高亮得引 Pygments，约 3MB，跟「轻量」冲突）。

> 依赖：`markdown`（纯 Python，无 C 扩展，约 200KB）。打包时 `build.spec` 用
> `collect_submodules("markdown")` 把它的扩展一起收进去 —— 扩展是运行时按名字动态 import 的，
> 不显式收集打包后会报 `ModuleNotFoundError: markdown.extensions.extra`。

## 工具四：MD浏览器

和「JSON转MD」的区别一句话说清：**那个要先有 JSON 还要挑正文键，这个什么都不要**，
把 Markdown 原文贴进来就直接看排版。从公众号、Typora、ChatGPT 里复制出来的 Markdown、
本地 `.md` / `.txt` 文件都能用。

- 左边贴 Markdown，右边 **150ms 防抖实时渲染**，不用点按钮；
- 底部三个按钮：**打开文件**（`.md` / `.markdown` / `.mdown` / `.txt`，UTF-8 / GBK 自动识别）、
  **从剪贴板**、**清空**；
- 标题栏右侧：**搜索**（<kbd>Ctrl</kbd>+<kbd>F</kbd>，和 JSON转MD 同一套）、**复制**、**大窗口预览**；
- 底部「更新预览」或 <kbd>Ctrl</kbd>+<kbd>Enter</kbd> 可立刻重绘，下面显示「更新于 hh:mm:ss」；
- 渲染器、缩放、搜索全部**复用 `jsonmd.py`**（`build_html` / `PreviewWindow` / `FindBar`），
  所以三个预览地方的样式与手感完全一致，以后改样式只改一处；
- 只做标题规范化（`#标题` → `# 标题`，同 JSON转MD），**正文一个字都不改** ——
  这里不需要「挑正文」，粘什么渲染什么；
- 超过 20 万字符时字符数变黄提醒（Python-Markdown 会明显变慢），但不拦。

## 工具五：翻译

左边原文、右边译文，用的是阿里云百炼的 **Qwen-MT 机器翻译专用模型**
（[官方文档](https://help.aliyun.com/zh/model-studio/machine-translation)），走 OpenAI 兼容端点
`https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`。

**要先在设置里填 API Key**，否则点「翻译」会提示缺少 Key。

### 三档模型

| 档位 | 模型 | 语种数 | 适合 |
|---|---|---|---|
| 快速 | `qwen-mt-lite` | 31 | 短句、聊天、随手翻 |
| 普通 | `qwen-mt-flash` | 92 | 通用首选，速度与质量平衡（默认） |
| 高级 | `qwen-mt-plus` | 92 | 论文、合同、技术文档 |

三档都**不开流式、不带记忆**（Qwen-MT 本身不支持多轮，连发反而会报错）。
当前用的模型名显示在档位按钮右边，随时能确认打的是哪个。

### 风格（改变语体）

风格和领域**都通过 `translation_options.domains` 传给模型**，`messages[0].content`
里**只放原文**，一个字的额外提示都不加。内置：默认 / 日常交流 / 学术论文 / 正式场合 /
商务邮件 / 技术文档 / 口语字幕。

> **为什么不用「提示词拼在正文前面」的写法**（官方文档 8.8 那种）：
> `content` 是这个模型的**待翻译正文**。一旦把
> `Translate the following text into formal academic prose…` 这种指令拼进去，
> 模型会把它当成正文的一部分一起输出 —— 表现就是译文开头多出
> 「本报告采用正式的学术文体，适用于同行评议期刊。请使用精确的工程术语…」，
> 严重时整段译文只剩一句领域描述，甚至把 `terms` 的内部结构
> `{"src": "tolerance", "tgt": "tolerance"}` 一起吐出来。
>
> `domains` 是请求元信息，模型只拿它当背景调整语体，**永远不会把它写进译文**。
> 代价：里面必须写**描述性短语**（「正式学术散文：精确术语、无人称客观语气」），
> 不能写祈使句（「请翻译成正式学术散文」）。内置的都按这个规范重写过了。

**自定义风格**：设置 → 翻译 → 风格列表底部「＋ 添加」，填名称 + 描述即可，
可以加任意多个，存 `data/settings.json`，下拉框里立刻能选到。
提示词**建议写成英文描述而不是命令句**，设置面板里也写了这个提醒。

### 领域（改 domains + 术语）

领域改两样东西：`translation_options.domains`（英文领域描述，**官方只支持英文**，
所以内置的领域描述都写成英文）和 `terms`（术语表，`[{source, target}]`）。

内置：通用（无术语）/ 计算机 / 医学 / 法律 / 机械工程 / 金融 / 跨境电商，每个 10~12 条术语。

**自定义领域**：设置 → 翻译 → 领域列表底部「＋ 添加」，填名称、英文描述、术语表。
术语每行一条，`原文<Tab>或= 译文` 都认（比如 `服务器=server`）。

> 只有**原文里真的出现了**、**且原文和译文不一样**的术语才会写进 `terms` ——
> 不然一百条术语全发过去，白白吃掉几百 token；`公差 → tolerance` 这种占位条目
> （两边都写 tolerance）发给模型只会让它犯迷糊，也一并跳过。

### 输入上限 12000 单位

上限不按「字符数」算，用一个**按显示宽度折算的「单位」**：
**中日韩文字 / 全角标点 / emoji 每个算 2 单位，英文、数字、符号每个算 1 单位。**

理由：中文一个字在屏幕上顶两个英文字符宽，token 也贵 4 倍（0.66 vs 0.15）。
用统一尺度，中英文手感才对得上。所以：

| 输入 | 等于多少 |
|---|---|
| 纯中文 | 6000 字（12000 单位） |
| 纯英文 | 12000 字符（12000 单位） |
| 3000 汉字 + 6000 英文 | 正好 12000 单位 |

Qwen-MT 的输入上限是 **8192 token**，按字符类别分别实测（每类各 4000~10000 字符）：

| 内容 | 实测 token/字符 | 10000 字符约需 |
|---|---|---|
| 普通中文 | 0.66 | 6597（安全） |
| 中文 + 学术风格 + 法律术语 | 0.66 | 6635（安全） |
| emoji 混排 | 0.68 | 6785（安全） |
| 英文 | 0.15 | 1458（很宽裕） |
| ASCII 标点 / 符号 | 0.60 | 6018 |
| **数字 0-9** | **1.01** | **10070（超限）** |
| 数字+符号交替（报表串） | 1.17 | 11700（超限） |

> 最容易踩的坑是**数字**：它几乎 1 token/字符，比汉字还贵。
> 所以「一万字的报表/参数表」会比「一万字的文章」贵一倍多。

12000 单位换算成 token：6000 汉字 ≈ 4000、12000 英文 ≈ 1800、中英各半 ≈ 4900 —— 全都安全。

同时**发送前再用 `estimate_tokens()` 预检一次** —— 估算按上面那张表分类加权，
估算值超过 7800 就当场拦下，并告诉你大概该减到多少：

> 这段内容 token 太密（≈8117，上限 8192），请删到约 6900 单位再翻

这样既不用为了极端的报表把上限压得很低，也不会等阿里云返回 400 才知道超了。

超出上限**不会再让输入**（不是事后报错）：打字打到头会弹提示，粘贴会被截断到剩下的空间
（`fit_units()` 按单位算，不会把汉字劈一半）。
输入框右上角实时显示 `1234 / 12000 单位`，鼠标悬停能看到「本段 N 个字符 → M 单位」，
下面还有一行 token 粗估。单位数或估算 token 任一项接近上限，计数就会变黄/变红提前预警。

### 不做实时翻译

必须点「翻译」按钮才发请求 —— 实时翻译等于每敲一个字烧一次 token。

### 粘贴时自动纠正目标语言

有个很容易踩的坑：源语言设成「自动检测」、目标语言设成「简体中文」，然后粘一段中文进来，
模型会老老实实「中译中」，译文跟原文一模一样，看着像坏了。

所以**粘进来的那一刻会立刻判一次语言**（`detect_lang`）：按字符构成统计，
汉字或拉丁字母占 **≥80%** 才认，且日文（有假名）、韩文（有谚文）、纯数字、代码一律不认。
判出来如果**跟当前目标语言是同一种**，就自动把目标切成另一种（中 ↔ 英），
源语言顺手切到「自动检测」，并弹一条提示：

> 检测到中文内容，目标语言已自动改为英语（可手动修改）

**只在中 / 英之间判断**，而且改完你随时可以手动改回去，它不会跟你抢。
日文、韩文、中英混排（不到 80%）都不会触发。

### 译文框

- **大窗口预览**：右上角按钮开独立窗口，可拉伸、`−` / `+` / `重置` 缩放（60%~240%），
  也支持 <kbd>Ctrl</kbd> + 滚轮。
- **MD 格式查看**（大窗口标题栏那个按钮）：译文里常带着 `#`、`**`、`|表格|` 这些 Markdown
  标记（原文是 Markdown 时模型也照原样搬过来），纯文本看着全是符号。
  点一下「MD 格式」，就用和「JSON转MD」**同一套渲染器**排出来；按钮变成蓝色「纯文本」，
  再点一下切回去。切换时会回到顶部，免得上一次的滚动比例套到完全不同的排版上。
- **搜索**：<kbd>Ctrl</kbd>+<kbd>F</kbd> 或放大镜按钮，输入即高亮并显示「3/12」，
  <kbd>Enter</kbd> 下一个、<kbd>Shift</kbd>+<kbd>Enter</kbd> 上一个、<kbd>Esc</kbd> 关闭。
  搜索框内联在标题栏那一行，不会把正文往下挤。两种模式（纯文本 / MD）下都能搜。
- **复制** / **统计字数**：后者把译文直接塞进「字数统计」并跳过去。
- 译文下方显示这次用了多少 token，以及累计用量。

### 翻译历史

译文框右下角的「历史」按钮。每翻成功一次就自动存一条（原文 + 译文 + 当时用的
语种/档位/风格/领域/token 数），点列表里的任意一条，**另开一个窗口**左右对照看。

- **存哪**：**系统临时目录**（Windows 上是
  `%TEMP%\猫娘工具箱-翻译历史\`），不是 exe 旁边的 `data/`。
  理由：译文往往是大段文字，攒几十条就几十兆，而历史只是「回头看一眼」的便利功能，
  不值得长期占盘。放 temp 里，关机/清理时系统自己会删掉，不用管。
  想立刻清掉就点历史窗口里的「清空」，或「打开文件夹」手动删。
- **容量**：最多 100 条 / 20 MB，超了从最旧的开始丢，不会无限长。
- **列表里显示**：原文摘要（一行）+ `时间 · 方向 · 档位 · 风格 · 领域`。
  今天只显示时分秒，更早的带上日期，一眼分清新旧。
- **详情窗口**：左原文、右译文，右上角「复制原文 / 复制译文 / 载回翻译页」。
  「载回翻译页」会把原文填回翻译输入框（同样不会自动发请求）。
- **存储结构**：`index.json` 存所有条目的元信息，正文明细单独放 `items/<id>.json` ——
  列表只读 index，不会为了显示 10 条去把几十兆正文全读一遍。

### 设置 → 翻译

- **API Key**：密码框，可点「显示」查看。存在 `data/settings.json` 里，**不写进代码、不进 Git**。
- **测试连通**：拿一句短句真打一次接口，能立刻区分「Key 错了」「欠费了」「网络不通」。
- **打开百炼控制台 · API Key** / **查看用量与账单**：跳浏览器。
  > 百炼**没有开放余额查询接口**（`/api/v1/billing`、`/usage`、`/account/balance`
  > 等路径全部 404），所以只给跳转，不做余额显示。累计 token 是本地自己记的，仅供参考。
- **风格列表** / **领域列表**：内置的只读，自定义的可编辑、可删除。

### 已知限制

1. `qwen-mt-lite` 只支持 31 种语言，选了它不支持的语种会报「语种代码不被该档位模型支持」，
   换「普通」或「高级」即可；
2. 译文本身是**纯文本**，Qwen-MT 不保证保留原文的段落缩进、嵌套列表这些结构。
   Markdown 标记（`#`、`**`、表格）能原样留在译文里，靠大窗口的「MD 格式」看排版；
   但如果你翻译的是**普通 Word 文档正文**（没有 Markdown 标记），MD 模式下也不会有标题层级。
3. 术语干预是「建议」不是「强制」，模型偶尔仍会用同义说法。
4. **历史存在 temp 里**，系统清理磁盘、关机、或手动清空临时文件后就没了；
   要长期留存请自己「复制译文」存到别处。
5. 极端报表（几乎全是数字和符号）到不了 12000 单位 —— 数字是 1 token/字符，
   这种内容在 ~7800 单位就会被预检拦下并提示该减到多少。

## 换台电脑 / 发给朋友能用吗

能。exe 是**单文件便携版**，Python 解释器、PySide6、Qt 以及 VC++ 运行时（`MSVCP140` / `VCRUNTIME140`）全都在 exe 里面，目标电脑**不需要装 Python，也不需要装任何依赖**，双击就跑。

实测：把 exe 单独拷到一个空文件夹（没有 `data/`、没有 `喵语.txt`）里运行，窗口正常起来，并自动在旁边生成 `data/` 和 `喵语.txt`。

需要注意的几点：

- **系统要求**：Windows 10 / 11，**64 位**。32 位 Windows 跑不了（打包的是 64 位）。
- **多标签恢复需要 Win11**：这套恢复靠点资源管理器标签栏的「+」实现。Win11 有标签页，功能完整；Win10 没有标签栏，多标签那部分会失败——每个窗口的第一个文件夹仍能打开，其余的在结束弹窗里报「无法新建标签页」。
- **不需要管理员权限**，普通用户双击即可。
- **首次运行可能弹 SmartScreen**：「Windows 已保护你的电脑」——因为没做代码签名，点「更多信息 → 仍要运行」即可。个别杀软对 PyInstaller 打出来的 exe 会误报，加个信任就行。
- **数据各自独立**：记录和预设存在各自电脑的 `data/` 里，不跟着 exe 走。想把自己的配置带过去，把 `data/` 和 `喵语.txt` 一起拷。**注意 `data/settings.json` 里有翻译的 API Key**，发给别人前记得先清掉。
- **体积约 50 MB**：Qt 运行时本身就这么大，正常。压缩包发微信/QQ 都没压力。第一次启动约 2 秒（要先解压），之后会快一些。

## 实现说明

恢复用的是「UI 自动化点标签栏的 + 按钮 + 通过 Shell 接口导航」，全程不模拟鼠标移动，也不抢焦点。因为 Windows 11 的资源管理器没有提供任何能新建标签页的公开接口，点 + 是唯一可靠的途径；好处是标签顺序严格可控，代价是每个标签约 1 秒（资源管理器自己的建标签动画延迟）。

## 界面说明

- 左上角是透明背景的猫娘头像 + 标题；再往下是**竖向排列**的两个页面入口（文件夹恢复 / 预设），猫娘立绘压在这个窄栏的左下角，不挡内容。
- 按钮图标全部来自 `assets/*.svg`，用 Qt 的 SVG 渲染器按 2 倍分辨率绘制，高 DPI 下不发虚。
- 主窗口右下角有红色的「按 Esc 紧急中止」提示（纯文字、无边框）。

### 窗口大小 / 移动 / 最大化

界面是以 **1120×780** 为设计基准做的，窗口是**无边框**的，下面这些操作都是自绘实现的：

**改大小**
- 鼠标移到窗口四边 / 四角（边框内侧 5~14px），光标变成缩放箭头，按住拖动即可；
- 拖动时保持 1120:780 的长宽比，内容永远铺满，不会留白或裁切；
- **松手之后**整体按新尺寸重排一次：字体、间距、圆角、图标、猫娘立绘一起等比缩放；
- 缩放范围约 0.62×～1.6×（694×484 ～ 1792×1248）。

**移动窗口**（两种方式，任选）
- 拖顶部标题栏；
- 拖窗口**四周约 22px 宽的那圈空白背景**——等比放大后标题栏可能被顶到屏幕外，这时就靠这圈空白把窗口拖回来。

**最大化 / 还原**
- 标题栏右侧的 `□` 按钮，或**双击标题栏**；
- 最大化时铺满整个工作区（此时拉伸手柄自动禁用，避免误拖），再点一次（按钮变成 `❐`）回到原来的位置和大小；
- 最大化状态下直接拖标题栏，会先还原成小窗再跟着鼠标走，和系统窗口的手感一致。

启动时会按屏幕可用区域自动选初始大小（大屏用 100%，2.5K / 高缩放比的屏自动缩到刚好放得下）。

> 为什么缩放只在松手时做：Qt 里改缩放等于整窗重新排版一次（约 0.2~0.5 秒），拖动过程中每帧都做会卡；所以拖动时布局先自适应跟随，松手后再统一按比例重排。

### 拔掉外接显示器后自动回主屏

笔记本接了外接屏、把窗口拖到外接屏上，然后**拔掉显示器**（或切到「仅笔记本屏幕」）时，
窗口坐标会留在那块已经不存在的屏幕上 —— 系统上窗口还在，但人看不见，等于程序消失了。

Qt 的 `screenChanged` 信号只在「窗口自己换屏」时发，**拔屏时窗口并不会自己换屏**，
所以光靠它救不回来。这里改成了听 `screenRemoved` / `screenAdded` / `primaryScreenChanged`
以及每块屏的 `availableGeometryChanged`，任意一个触发就做一次自检：

- 用 **可见面积占比** 判断，而不是「窗口中心在不在某块屏里」—— 窗口只露一条边的时候
  一样没法用，得当成不可见；
- 占比低于 45% 就视为「跑到屏幕外了」：先 `showNormal()`（最大化状态坐标是系统给的，
  不先还原改了也没用），再按主屏重算缩放系数（外接屏 4K、笔记本 2.5K 的缩放不一样），
  最后缩到主屏可用区内居中；
- **翻译/恢复正在跑的时候不重建界面** —— 重建会丢掉正在等回调的页面，后台线程的结果
  就打到已删除对象上了；
- 顺手把跑到屏幕外的**子窗口**（设置、大窗口预览、翻译历史…）一起拉回来。
  这里有个坑：不能用 `QApplication.topLevelWidgets()`，它只返回**没有 parent** 的窗口，
  而这些对话框的 parent 都是主窗口，压根不在里面；得从 QObject 子树找 + `isWindow()` 筛。
- 启动时也会自检一次（万一上次是拔了屏才关的）。

## 重新打包

在仓库根目录执行：

```bash
pip install -r requirements.txt

# 产物落到 dist/，中间文件丢到 build/（两者都被 .gitignore 忽略）
pyinstaller build.spec --distpath dist --workpath build
```

打出来的 `dist/猫娘工具箱.exe` 就是单文件便携版：拷到任何空文件夹双击即可，第一次运行会在旁边生成
`data/` 和 `喵语.txt`。`data/` 和 `喵语.txt` 都是运行时生成的，不要打包进 exe、也不要提交到仓库
（`data/settings.json` 里有翻译的 API Key）。

### 改图标

图标源文件是 `assets/app_icon.svg`（圆形版）。改完先重新生成 `app.ico` 再打包：

```bash
python make_ico.py        # 生成 16~256 共 10 个尺寸的 app.ico，以及 512 的圆形 app_icon.png
pyinstaller build.spec --distpath dist --workpath build
```

⚠️ 这里有个坑：QtSvg 只支持 SVG Tiny 1.2，**不认 `clip-path`**。这个 SVG 是靠
`<g clip-path="url(#roundClip)">` 裁成圆的，直接渲染四角会被背景矩形填满、看起来是个方块，
所以 `make_ico.py` 里按 SVG 的半径（512 视图下 r=252）自己加了一条圆形裁剪路径；
`assets/app_icon.png` 也是同一个渲染流程出的（圆形 + 带渐变底），不要手工抠图覆盖它。

> 换完图标后 Windows 资源管理器可能仍显示旧图标（按路径缓存）。刷新（F5）不行的话，
> 把 exe 改个名再改回来，或重启资源管理器即可；新建的快捷方式肯定是新图标。
